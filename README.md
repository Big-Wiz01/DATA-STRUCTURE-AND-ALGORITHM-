## What it does
The program reads arithmetic expressions from `input.txt`, evaluates each one with
a stack-based algorithm, and writes the results to `output.txt` in the same layout
as the input (one result per line, with the same separator lines).

## Requirements
Python 3.8 or newer. No external libraries are needed.

## How to run
1. Put `stack_evaluator.py` and `input.txt` in the same folder.
2. Open a terminal in that folder and run:

       python stack_evaluator.py

3. Open `output.txt` to see the results.

Custom file names can be passed as arguments:

       python stack_evaluator.py my_input.txt my_output.txt

To run the unit tests:

       python -m unittest -v test_stack_evaluator

## Input file format
- One expression per line.
- Expressions are separated by a line containing only a separator (e.g. `-----`).
- Blank lines are ignored.

Example `input.txt`:

    3 + 5 * 2
    -----
    (8 / 4) + 7 * 2
    -----
    10 - (2 + 3) * 4

## Output file format
Each expression is replaced by its result; separator lines are copied unchanged.

    13
    -----
    16
    -----
    -10

## How it works
Two stacks are used (a variant of Dijkstra's shunting-yard algorithm):
- an **operand stack** that holds numbers, and
- an **operator stack** that holds operators and opening brackets.

When a new operator arrives, operators on top of the stack with higher or equal
precedence are applied first. `*` and `/` therefore run before `+` and `-`, and
brackets are resolved when `)` is reached.

## Assumptions and limitations
- Supported operators: `+`, `-`, `*`, `/`, parentheses `( )`. Powers and modulus are not supported.
- Unary minus (`-5`, `2 * -3`) and decimals (`2.5`) are supported.
- Division always gives a decimal result; whole numbers are shown without `.0`
  and other results are rounded to 6 decimal places.
- Each expression must be on a single line.
- Invalid expressions (division by zero, unbalanced brackets, bad characters,
  missing operands) do not crash the program; the output line says
  `Error: <reason>` and the rest of the file is still processed.
- **Note on the brief's sample:** the brief shows `17` for `(8 / 4) + 7 * 2`, but the
  correct value is `8/4 + 14 = 2 + 14 = 16`, which is what the program outputs.
